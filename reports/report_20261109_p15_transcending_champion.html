一、 五大核心配方特點深度剖析 (Five Core Architectural Features)

1. 2M 多流共享池與單請求 1M 上下文解耦 (2M Multi-Stream KV Pool vs 1M Context Decoupling)

  • 解耦架構 (Decoupled Windows)： 透過 Patch 0063 (TF_DS_WINDOW)，將底層多流共享池容量固定為 2,097,152 tokens，同時保持單請求上下文窗口上限為 1,048,576 tokens，徹底消除歷史斷言崩潰 (assert(total_ctx <= pool_cap))。
  • 記憶體緊湊化 (Memory Density)： MLA 潛在特徵解碼僅需 890 Bytes/Token/Rank，雙機總池實體佔用僅 1.74 GiB，為大並發留下充沛顯存空間。

2. 安全約束型動態工作竊取 (Optimal Erlang-Pooling Safe Work-Stealing Arbiter)

  • 槽位彈性借調 (Borrowable Slot 7)： Slots 1~6 為全優先級共享池；當活躍數達到 6 且隊列中無可立即運行的 P0/P1 緊急等待時，背景 P2 獲准借調 Slot 7（消除了大預填等待造成的假死鎖），背景可用槽位擴展至 7 個（對齊 P11 歷史最高標準）。
  • 神聖保留槽 (Sacred Slot 8)： Slot 8 嚴格禁止任何 P2 背景任務進入，為 P0 互動式高優先級流量提供絕對零等待通道。

3. 基於 3.05 GiB 穩態水位的主動預填流水線屏障 (Dynamic Prefill Barrier with First-Token Overlap)

  • 動態階梯准入 (Memory-Aware Ladder)： RAM ≥ 3.05 GiB 允許 3 路 >20K 大預填並發；2.65 GiB ≤ RAM < 3.05 GiB 允許 2 路；< 2.65 GiB 僅允許 1 路。精準適配 3.20~3.55G 穩態顯存，消滅 22K 任務的排隊延遲。
  • 暖快取完全豁免 (Warm Cache Exemption)： 命中已提交前綴快取之任務，工作空間標記為 512 tokens，不受大預填屏障阻擋，即到即進。
  • 首字即時釋放 (Prefill-Decode Pipeline Overlap)： 一旦大預填完成並吐出第一個生成的 Token Delta，立即遞減預填佔用計數器，解鎖下一筆預填進場。

4. MS-DTC 動態溫控變速箱 (Multi-Stream Dynamic Thermal Compensation Governor)

  • 平滑調頻步進 (50 MHz Stepping)： 調頻步長由 150 MHz 細化為 50 MHz，消滅高壓震盪；
  • 軟夾持防崩潰 (2200 MHz Soft Clamp)： 89°C 警戒線觸發時改為軟夾持於 2200 MHz（禁止崩潰至 1800 MHz），維持單流貪婪解碼速率於 92+ tok/s。
  • 甜區極限釋放 (Sweet-Zone Burst)： 待機 2400 MHz（板載功耗僅 9.4W）；負載進場且溫度 < 84°C 時爆發至 2500 MHz。

5. DSML 工具調用即時增量串流與思維剪枝 (DSML Token-Level Streaming & Reasoning Pruning)

  • 即時狀態機 (Patch 0048)： 原生支援 <|DSML|invoke> 工具調用 Token 級增量串流，首字延遲僅 0.694s。
  • 歷史思維剪枝 (PR #116 / Patch 0057)： 啟用 --drop-reasoning-history --keep-last-n-reasoning 2，多輪對話自動剪除陳舊推導，KV Cache 空間重用率暴增 300%。
  • 自適應 P0 視窗 (14~16s Window)： P0 享有 14~16s 隊列保護，徹底杜絕 10.0s 硬限時斬首多輪讀圖 Turn 2 的弊病。
