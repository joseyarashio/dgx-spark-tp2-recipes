- **依 S2 預先登記的閘門,本階段判定為 FAIL。**

  - 系統層級收益估計只有約 0.5–1.2% 忙碌時間;

## (1) 量測方法與數據盲點

**A. 基線決定性:強證據,但不等於「批次不變」的證明。**

- A1 與 A2 的 500/500 文字完全相同,generation_tokens 同為 101,028。
- 但 decode_rounds 為 44,582 對 44,541,drafted 為 58,541 對 58,482。這表示兩次執行的排程與 draft 深度確實不同,輸出卻仍一致。這是批次不變性的強證據【推論】。
- 這次沒有和單流 sha 交叉比對。以「首次分歧」近似 teacher forcing,前提是 A 與批次組成無關;目前這個前提只被間接支持。

**B. 翻轉率的推導與限制。**

- 1.1%/token 的來源:每次分歧約 324 chars 共同前綴,換算約 90 token,所以 1/90 ≈ 1.11%【計算】。
  - 但 chars/token = 3.6 是推論值。應直接用 tokenizer 計算分歧 token 位置。
  - 即使比值誤差達 2 倍,翻轉率仍 ≥ 0.55%,依然不過門檻【計算】。
- 統計不確定性很小:382 個事件,Poisson 相對誤差約 ±10%,95% 區間約 1.0–1.2%/token【計算】。
- 危險率集中在前段:
  - 若服從指數分布,中位數應為 ln2 × 90 ≈ 62 token【計算】;
  - 實測中位數 119.5 chars ≈ 33 token【計算】,明顯更早。
  - 可能的解釋是:開頭措辭階段多為近似平手(near-tie)的 token,或 8 流同時起步時聯集最大【推論】。
- 事件之間不獨立。在 B 下,一個 stream 分歧後會改變同批 routing 聯集,進而引發鄰居的次級翻轉。這種耦合在生產環境中同樣存在,所以不算偏差,但不能把 382 個事件當成獨立樣本。
- **缺 B/B 重複。** B 的輸出取決於當下同批鄰居,而鄰居取決於時序。B1 重跑很可能得到不同文字。所以可重現性的喪失不只是「A 與 B 不同」,更可能是「B 與 B 也不同」【推論】。這一點未量測。
- **缺「無害擾動」的參考翻轉率。** 例如改變累加順序、換 TP 切分或關閉 MTP 時,翻轉率是多少?沒有這個參考,無法判斷 1.1% 對這個模型來說是大還是小。這也是我在 S2 設 0.5% 門檻時的弱點,但門檻既已預先登記,事後不應改動。

**C. 觸發率的歸因需要更正。**

- dossier 將觸發率只有 45.4% 歸因於尾段 stream 數 < 5,但計數器數據不支持這個說法:
  - 每次 layer-call 平均 stream 數 = 1,772,400 / 256,000 = 6.92【計算】。
  - 未觸發的呼叫,平均聯集 = (12,327,659 − 52.3 × 116,122) / 139,878 ≈ 44.7【計算】,已低於 48。
- 結論:主要原因是 cap 本身沒有被綁到,不是 stream 不足【推論】。
- 需要再加一個計數器:「stream ≥ 5 但聯集 ≤ cap」的呼叫數。

**D. 成本模型與吞吐的對帳(大致吻合)。**

| 項目 | B1 | C1 |
|---|---|---|
| 每次呼叫平均減少的 expert 數【計算】 | 3.40 | 13.3 |
| 依 28.6 µs/expert/layer × 40 層,每回合節省【計算】 | ≈ 3.9 ms | ≈ 15.2 ms |
| 牆鐘 / device 回合【計算】 | 103 ms(660.8 s / 6,400) | 92 ms |
| 預測吞吐提升【計算】 | ≈ +3.9% | 與 +15.1% 量級一致 |
| 觀測吞吐提升 | +2.7% | +15.1% |

- 成本模型可信。B 的實測略低於預測,可能來自 launch 開銷或回合中的非 MoE 時間【推論】。

**E. 丟棄權重的劑量反應一致,但每列分布缺失。**

- 每個被丟 slot 的平均權重:B ≈ 0.087,C ≈ 0.102【計算】。
- 以每回合約 15.7 列粗估(100,645 token / 6,400 回合),每列被丟的權重比例約為:B ≈ 4.3%,C ≈ 9.6%【推論】。C 的數字與 S1 模擬的 11.1% 一致。
- `max_rescale` 達 2.54(B)與 5.76(C):至少有一列只保留了 39% 和 17% 的 routed 權重。
  - 這是 S2 R5 預警的尾部風險。
  - dossier 只給了最大值,沒有分布。每列丟棄比例那一行的文字也被截斷。

**F. 其他盲點。**

- **「External POSTs: see header line」所指的行未附上。** 無法確認 S3 期間是否有外部流量混入,這是必要的污染證據。
- **AIME 受 429 嚴重混淆。** A 有 6 次 429,B 有 10 次,差異不對稱。兩邊都有作答的 18 題中只有 1 題不一致,資訊量趨近 0。
  - 附帶的維運發現:8 條長 thinking 串流會讓 X-Priority 2 在 25 s 後被拒。這應另開工單處理。
- **速度只有 1 次重複,且未採 ABBA。** A1 與 A2 相差 0.16%,顯示漂移很小,所以 +2.7% 大概是真的【推論】,但不符合 S2 預先登記的設計。

### 可成立

1. 基線在 C8 封閉迴路下完全可重現,且對排程擾動不敏感。
2. 4:48:5 在 GSM8K C8 下,每 token 會以約 1% 的速率改變 greedy top-1,影響 76% 的回應。

- **「正確率在界內,所以品質無損」不成立。**

- **「觸發不足是因為尾段 stream 少」不成立。** 見 1C。
- **AIME 不能拿來支持任何方向的結論。**
- **「4:32:5 正確率相同、快 15%,所以更值得」是危險的推論。** 它的翻轉率約 2.1%/token【計算】,最大 rescale 5.76,而且 GSM8K 對它根本沒有鑑別力。

## (3) 下一階段是否值得做與具體參數

### 系統層級收益估計

- 生產環境中 ≥5 streams 的時段占忙碌時間 20.1%。
- 以 +2.7% 計:節省約 20.1% × (1 − 1/1.027) ≈ **0.53%** 忙碌時間【計算】。
- 以 S2 decode-gate 的 +6.3% 計:約 **1.2%**【計算】。
- 混合領域的生產批次可能讓 cap 綁得更緊,收益和傷害都會變大【推論】。

### 代價

1. **喪失 A/A 位元一致性。** 這目前是除錯、回歸測試與評測可重現性的基礎。
2. **翻轉率超過預先登記門檻 2 倍。**
3. **少數派不公平性未量測。** 外部 MacBook 客戶端有 46.6% 的 token 落在 ≥5 流時段,正是最可能吃虧的族群【推論】。
4. **opt-in 也有維護成本。** 包括 kernel、env 解析、2D 拒絕路徑、測試面,以及被誤開的風險。

### 結論:不值得再投入 S4,建議移除

- 1% 量級的收益,不足以抵銷上述代價,也撐不起一套真正有鑑別力的品質驗證。
- 「有鑑別力的驗證」至少需要:teacher-forced logits/KL、難題集、B/B 重複、少數派批次。估計要 4–6 小時 GPU 加上 logits API 的工程。
- 問題 2 的答案:**移除,不保留 opt-in。** 這符合「只保留經量測、可辯護的收益」原則。

### 封存與重開條件

- 程式碼、離線 C++ 參考、device 計數器與 S1–S3 dossier 一併封存於分支。
- 任一條件成立才重開【建議值】:
  1. 生產中 ≥5 streams 的 token 占比 > 50%;
  2. 出現批次不變的設計,例如每列 keep 集合只由該列決定,或保證每列保留權重 ≥ 90%;
  3. 已有 logits API,可以直接量 KL。

### 若產品端仍堅持保留(不建議),發布前的最低要求

| 項目 | 參數【建議值】 |
|---|---|
| 少數派批次測試 | 1 個中文或數學 stream + 7 個 code stream,8 次輪替;少數派翻轉率 ≤ 1.5 倍多數派 |
| B/B 重複 | 確認並記錄 B 的不可重現程度 |
| loop probe | C8 下 0 新增 |
| 速度 | ABBA,≥ 3 次重啟,C8 ≥ +4%;否則撤回 |
| 每列保底 | 新增 per-row 保底:保留權重 < 70% 的列不丟棄,以封住 max_rescale 的尾部 |
| 計數器 | 加入 stream ≥ 5 但未觸發的計數 |
| 預設與文件 | 預設關閉;文件明示「開啟後輸出與批次相關、不可重現」 |

## gpt-6-astra (ok=True, finish=stop, wall=95.7s)

## 1. 量測方法與數據盲點

**總評：本次不足以通過 S3；更重要的是，目前收益不足以支持直接進入完整發布階段。** 實作修正與離線對帳值得肯定，但「實作符合參考」不等於「近似計算的品質代價可接受」。

### 量測設計仍有三個核心缺口

- **A1→B1→C1→A2 不是預先登記的 ABBA，且每臂只有一次。** A1/A2 吞吐僅差約 0.16%【計算】，是有用的穩定性證據，但不能據此估計 B 的跨重啟變異，更不能把 500 題當成 500 次獨立速度實驗。各臂是否跑 AIME 也不同，不能排除前序負載的影響【推論】。
- **「C8」是客戶端並發，不是每個解碼回合都有八條活躍串流。** B 只有 45.4% layer-calls 觸發，不能全部歸因於尾段 streams <5：符合串流門檻但 union 不需裁減，也可能不觸發【推論】。需要按未觸發原因拆分。
- **計數器範圍尚未對帳。** B 的 device `rounds=6400`，但 `/metrics` decode rounds 為 44,378；兩者可能合理地使用不同定義，但 dossier 沒有說清楚。還只有 rank 0，不能驗證 TP=2 兩端的實際行為一致。外部 POST「0 expected」也不是觀測到零的證據。

### 翻轉率不能由字元摘要直接驗收

B 有 382/500 個文本分歧，但：

- 119.5 **字元的中位數**，不能與約 324 **字元的平均共同前綴**混用。
- 約 90 tokens 來自 chars/token 換算，不是實際 token 對齊。
- 約 1.1%/token 是近似推估，尚非預先登記指標的有效估計。

若沿用首次分歧的設限方法，分母必須納入**全部題目在首次分歧前的 token 暴露量，包括未分歧題目的完整暴露量**；EOS 差異也需一致處理。即使如此，它量的是既定前綴與批次條件下的首次分歧風險，不能無條件等同所有位置的 teacher-forced top-1 翻轉率。

### 成本模型需要降級為機制假說

- B 的總 union 減少 870,047，約為原 union 總量的 **7.1%**；C 約為 **27.5%**【計算】。這支持裁減確實發生，但不是 DRAM bytes 或牆鐘時間的等比例下降。
- 先前的 28.6 µs/expert/layer 斜率，不能在未對帳回合範圍、rank、執行路徑前直接套用。尚缺同窗口的實際 kernel 時間、記憶體流量及統計 instrumentation 成本。
- `dropped_weight_e6` 沒有 fired-row 分母及原始總權重，**不能產生可信的每列平均丟棄比例**。`sum_streams` 也不能代替 row 數。
- 最大 rescale 為 B **2.54 倍**、C **5.76 倍**【計算】。這不是品質損害的直接證明，但表示平均正確率可能掩蓋局部高擾動【推論】。

| 陽性對照 flips ≥1.5× B | **未定** | 文本分歧數比為 457/382≈1.20【計算】，但這不是 per-token flip 比；不能據此宣告通過或正式失敗。 |
| ABBA、至少三次重啟、C8 ≥+4% | **未達標** | 設計未滿足；本次 B 僅約 +2.7%，亦低於效果門檻。 |

**整體判決：不通過發布閘門。** 尚未測量的項目不是通過；也不必等所有缺項補齊，才承認目前速度項已不足。

### 結論的邊界

1. **A/A 的確很強，但只證明這兩次、相同題序的文本完全一致。** 沒有單流對照及換鄰居實驗，不能稱為「已證明全面 batch-invariant」。MTP 計數本身也不完全相同。
2. **B 對輸出擾動很廣泛：76.4% 文本分歧【計算】。** 這不等於 76.4% 品質受損，但足以否定「幾乎無行為代價」。
3. **McNemar p=0.625 不是等效證明。** 本題組只有四個 A/B 正誤不一致事件，而且基線 97.8% 已接近天花板。它可以排除此題組的大型退化，不能充分檢驗推理過程、工具行為或稀有失敗。
4. **C 是對裁減劑量有反應的證據，不是安全候選。** 它更快、分歧更早，但與 B 同為 487 題正確；這反而顯示 GSM8K 終局分數對這些擾動不夠敏感。
5. **AIME 只能判為污染。** 共同完成的 18 題也是經完成狀態篩選的子集，不能當成無偏配對樣本；不得將 22→17 全算成模型退化，也不得用它支持安全性。

## 3. 下一階段是否值得做與具體參數

**我的決策：不批准完整下一階段，也不批准對外 opt-in 發布；從正式發布範圍移除這項近似裁減，保留可重現的研究分支與資料即可。**

原因是收益與品質風險已不對稱：

- 生產 ≥5 requests 的占比跨過原先停止線，只表示「不是立即淘汰」，不是投資必然值得。
- proxy requests in flight 不等於裝置端可裁減的活躍 streams；25.7% token 占比也不能當成時間占比。
- 若**假設** 20.1% busy time 都能取得本次 +2.7% 加速，其餘完全無開銷，固定工作量的整體加速約為  
  \[
  [0.799+0.201/1.027]^{-1}-1 \approx 0.53\%
  \]
  【條件式推算】。即使用先前 +6.3%，同樣假設下也僅約 **1.2%**。這不是生產實測，更未扣除未觸發路徑成本。
- 對這個收益量級，尚未解決的輸出穩定性、少數派傷害、長推理與迴圈風險，沒有足夠安全證據作交換。**default off 只減少暴露，不會把未通過驗收變成可辯護功能。**

### 若團隊要求最後一次翻案機會

只批准有限的停損檢查，而非參數搜尋：

1. **先離線重新分析既有答案**：取得精確 token 首次分歧、含設限分母的 flip 指標、B/C 比值及逐題長度／finish reason。這一步若確認超過 0.5%，即停止。
2. 僅在上述通過後，固定 **TP=2、B=`4:48:5`、C=`4:32:5`**；不得因看到結果而放寬 cap 或品質門檻。
3. 下一個 GPU 檢查先做既定 **C8、ABBA、至少三次獨立重啟、≥+4%** 速度閘門，並完成計數器範圍對帳。失敗即結案，不再補完整品質套件。
4. 只有速度也過關，才執行原定跨領域三種排列、少數派輪替、工具／loop probe，以及排除 429 污染的長推理配對測試。**這些都仍是發布前最低缺項，不是上線後補件。**

## 4. 驗收門檻與回退條件

### 不更動原門檻

若保留翻案路徑，必須同時滿足：

- 精確 token 分歧指標、陽性對照倍率、少數派及 loop probe 全部完成並通過；不得用 GSM8K 正確率替代。
- T2 配對非劣性結論涵蓋有效長推理與跨領域樣本；429、超時及截斷分開列報，不得靜默排除。
- acceptance、長度、EOS／截斷維持原門檻。
- 速度符合原 ABBA／重啟設計，達到 ≥+4%；報告每次結果，而不只合併平均。
- 補上兩 rank、裝置實際串流數、觸發原因與計數器窗口對帳。離線零 mismatch 不能替代整合驗證。

**任何一項關鍵品質門檻失敗，或速度再次未達標，即停止本配置；不能以 C 的 +15.1% 抵銷 B 的失敗。**

### 建議立即採行的移除計畫

1. 正式服務維持 **off**，核對載入設定與已恢復的 `10d41f91174b005e`，不要只依賴 runner 的恢復訊息。
2. 從發布功能與設定介面撤下 budget；舊設定若仍被使用，應明確報錯，避免靜默忽略。
3. 移除專屬裁減 dispatch 與生產統計開銷；**不要機械式回退所有 S3 正確性修正**。哪些 `routed_only_y` 或其他安全修正仍被其餘路徑需要，應逐項審查。
4. 以既有 A 結果核對移除後輸出，並確認無裁減觸發、無殘留熱路徑開銷；封存程式版本、原始答案、計數器與本次未通過原因。

**最終判斷：這是一個有實際加速機制、但尚無足夠可辯護淨收益的近似功能。依「只保留已量測且可辯護收益」政策，現階段應退出正式產品，而非靠 opt-in 標籤延後品質決策。**
